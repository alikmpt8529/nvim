---
description: 変更内容を解析してコミットメッセージを自動生成し、git commitを実行する
---

以下の手順でコミットを作成してください。

1. 次のコマンドを並列で実行し、現在の状態を把握する:
   - `git status` (untrackedファイル確認。`-uall`は使わない)
   - `git diff HEAD` (ステージ済み・未ステージの変更内容)
   - `git log --oneline -10` (直近のコミットメッセージのスタイルを踏襲する)

2. 変更内容を分析し、変更の性質(新機能・改善・修正・リファクタ・ドキュメント等)を判断した上で、
   「なぜ」その変更をしたかに焦点を当てた簡潔な(1〜2文、50字程度)日本語のコミットメッセージを作成する。
   このリポジトリの既存コミットメッセージのスタイル(`feat:`, `fix:`, `refactor:`, `chore:` などの接頭辞)に合わせる。

3. `.env` や認証情報など、シークレットを含む可能性のあるファイルはステージングしない。
   もし機密情報を含みそうなファイルがあれば、ステージング前にユーザーに警告する。

4. 関連するファイルを明示的に指定して `git add` する(`git add -A` や `git add .` は使わない)。

5. ヒアドキュメントを使って以下の形式でコミットを作成する:

   ```
   git commit -m "$(cat <<'EOF'
   <コミットメッセージ>

   Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>
   EOF
   )"
   ```

6. `git status` を実行してコミットが成功したことを確認する。

7. pre-commitフックが失敗した場合は原因を修正し、再度ステージングした上で新しいコミットを作成する(`--amend`は使わない)。

ステージ・コミット対象になっていない変更がある場合は、含めるべきかどうかユーザーに確認してから進める。
